# Auth email templates (self-hosted Supabase / GoTrue)

These HTML files are fetched over HTTP GET by GoTrue at send time
(`internal/mailer/templatemailer/template.go`), then run through Go's
`html/template`. They are NOT processed by Next — `app/emails/[template]/route.ts`
returns the raw bytes, so the `{{ .Variable }}` placeholders reach GoTrue intact.

## They are internal-only

The templates used to sit in `public/`, which served them to anyone on the public
domain. They now live here (outside `public/`) and are served by a route handler
that answers **only callers on the internal Docker network**:

- the request must carry none of `x-forwarded-for` / `x-forwarded-host` /
  `x-forwarded-proto` — Traefik sets all three on anything it forwards, and an
  outside client cannot strip them; and
- its `Host` must be in `EMAIL_TEMPLATE_ALLOWED_HOSTS`
  (default `web:3000,127.0.0.1:3000,localhost:3000`).

Anything else gets a 404 — never a 403, so the public domain does not confirm the
path exists. `https://jobverifai.ronmrcdo.dev/emails/confirmation.html` is a 404
BY DESIGN; do not "fix" it.

## Where GoTrue fetches these from

Point `GOTRUE_MAILER_TEMPLATES_*` (set on the Supabase/auth container, which
lives in its OWN Coolify stack — not this repo's compose) at the container:

| Env var | Value |
| --- | --- |
| `MAILER_TEMPLATES_CONFIRMATION` | `http://web:3000/emails/confirmation.html` |
| `MAILER_TEMPLATES_RECOVERY` | `http://web:3000/emails/recovery.html` |
| `MAILER_TEMPLATES_MAGIC_LINK` | `http://web:3000/emails/magic-link.html` |
| `MAILER_TEMPLATES_EMAIL_CHANGE` | `http://web:3000/emails/email-change.html` |

Use the UNPREFIXED names — that stack's compose defines
`GOTRUE_MAILER_TEMPLATES_X: ${MAILER_TEMPLATES_X}`, so setting the `GOTRUE_`
name in the Coolify UI is overwritten by the interpolation. See PRODUCTION.md §3e.

GoTrue and `web` share the external `coolify` network, so GoTrue reaches the web
container directly by its compose service alias — no public exposure, no TLS, no
Traefik/Cloudflare in the fetch path. Plain http on the container port (3000).

Only the template SOURCE is internal — the link users click
(`{{ .ConfirmationURL }}`) is generated by GoTrue from SITE_URL / API_EXTERNAL_URL
and stays the public domain.

If `web` fails to resolve (another stack on the shared network aliases the same
name), use the Coolify-generated container name and add that `host:port` to
`EMAIL_TEMPLATE_ALLOWED_HOSTS` on the web service — the Host header GoTrue sends
is whatever is in the URL, and a host outside the allow-list 404s.

## Requirements for the fetch to work
1. `/emails` must stay excluded from the Next middleware matcher — the matcher
   runs on internal requests too, and would redirect an unauthenticated GoTrue
   fetch to the login page.
2. `emails/` must be present in the prod image. `output: "standalone"` does NOT
   trace it into `.next/standalone`, so apps/web/Dockerfile copies it explicitly
   in the `prod` stage. Without that COPY every /emails/*.html fetch 500s.
3. Adding or renaming a template means adding the filename to the `TEMPLATES`
   allow-list in `app/emails/[template]/route.ts` — an unlisted name 404s.

## GoTrue template variables used here
- {{ .ConfirmationURL }}  full verify link (confirm / recovery / magic / email change)
- {{ .Token }}            6-digit OTP (alternative to the link)
- {{ .Email }}            recipient address
- {{ .NewEmail }}         new address (email change only)
- {{ .SiteURL }}          site URL
- {{ .Data.<key> }}       user_metadata, e.g. {{ .Data.full_name }}

## A bad URL fails SILENTLY: an empty value, a DNS miss, or a 404 all fall
## back to GoTrue's built-in body and get cached. See PRODUCTION.md §3e to triage.

## GoTrue caches templates (default 10m). After editing, either wait out
## `GOTRUE_MAILER_TEMPLATE_MAX_AGE` or restart the auth container. The web route
## sends `Cache-Control: no-store`, so nothing else caches them.

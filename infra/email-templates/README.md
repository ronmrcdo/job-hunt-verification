# Auth email templates (self-hosted Supabase / GoTrue)

These HTML files are fetched over HTTP GET by GoTrue at send time
(`internal/mailer/templatemailer/template.go`), then run through Go's
`html/template`, so the `{{ .Variable }}` placeholders reach GoTrue intact.

## How they're served

A dedicated `email-templates` service (Caddy, `docker-compose.prod.yml`) serves
this directory over the shared external `coolify` network. It has **no Traefik
labels**, so nothing routes it from the public domain — the templates are
internal-only *by construction*. No header checks, no Host allow-list, no Next
route handler: an unexposed container simply cannot be reached from outside.

`Caddyfile` serves only `*.html`; anything else 404s, so this README and the
Caddyfile itself are never returned even though the whole dir is the web root.

## Where GoTrue fetches these from

Point `GOTRUE_MAILER_TEMPLATES_*` (set on the Supabase/auth container, which
lives in its OWN Coolify stack — not this repo's compose) at the service:

| Env var | Value |
| --- | --- |
| `MAILER_TEMPLATES_CONFIRMATION` | `http://email-templates/confirmation.html` |
| `MAILER_TEMPLATES_RECOVERY` | `http://email-templates/recovery.html` |
| `MAILER_TEMPLATES_MAGIC_LINK` | `http://email-templates/magic-link.html` |
| `MAILER_TEMPLATES_EMAIL_CHANGE` | `http://email-templates/email-change.html` |

Use the UNPREFIXED names — that stack's compose defines
`GOTRUE_MAILER_TEMPLATES_X: ${MAILER_TEMPLATES_X}`, so setting the `GOTRUE_`
name in the Coolify UI is overwritten by the interpolation. See PRODUCTION.md §3e.

GoTrue and `email-templates` share the external `coolify` network, so GoTrue
reaches the container directly by its compose service alias — no public
exposure, no TLS, no Traefik/Cloudflare in the fetch path. Plain HTTP on port 80.

Only the template SOURCE is internal — the link users click
(`{{ .ConfirmationURL }}`) is generated by GoTrue from SITE_URL / API_EXTERNAL_URL
and stays the public domain.

If `email-templates` fails to resolve (another stack on the shared network
aliases the same name), use the Coolify-generated container name in the URLs
instead. There is no Host allow-list to update — Caddy serves whatever host asks.

## Editing / adding templates
- Editing a template is a **redeploy of the `email-templates` service** (the dir
  is bind-mounted read-only) — no image rebuild. GoTrue then caches the new body
  for `GOTRUE_MAILER_TEMPLATE_MAX_AGE` (default 10m); wait it out or restart the
  auth container to see the change sooner.
- Adding a template is just a new `*.html` file here plus its
  `MAILER_TEMPLATES_*` env on GoTrue — no allow-list to edit.

## GoTrue template variables used here
- {{ .ConfirmationURL }}  full verify link (confirm / recovery / magic / email change)
- {{ .Token }}            6-digit OTP (alternative to the link)
- {{ .Email }}            recipient address
- {{ .NewEmail }}         new address (email change only)
- {{ .SiteURL }}          site URL
- {{ .Data.<key> }}       user_metadata, e.g. {{ .Data.full_name }}

## A bad URL fails SILENTLY: an empty value, a DNS miss, or a 404 all fall
## back to GoTrue's built-in body and get cached. See PRODUCTION.md §3e to triage.

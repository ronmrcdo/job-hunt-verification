# Closed Feedback → Eval Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a user's correction on their own investigation into a labeled eval case — user verdict → admin triage → operator-opened git PR into `eval/dataset.json` — and add a PR-blocking CI gate that runs the live eval whenever the band's decision logic changes.

**Architecture:** A real investigation's `submission` is already the exact shape an eval case needs, so "promote" copies the submission off the `investigations` row, attaches an admin-corrected `expected_max_band` + tags, and stages an `eval_candidate`. An operator script turns staged candidates into dataset-shaped cases and emits a diff for a human to merge. Two trust boundaries: any authenticated user may submit feedback about **their own** investigation (RLS `user_id = auth.uid()`); triage/promote is gated at the edge by Cloudflare Access and served by a server-only least-privilege Supabase client (`admin_ro`), never a permissive RLS policy.

**Tech Stack:** Next.js 16 / React 19 / TypeScript / vitest (apps/web), Postgres + Supabase migrations with RLS, Python 3.12 / pytest (apps/api eval + promotion script), GitHub Actions (CI gate), Cloudflare Access + `jose` JWKS verification (admin edge auth).

**Spec:** `docs/superpowers/specs/2026-08-26-feedback-eval-loop-design.md`

## Global Constraints

Copied verbatim from the spec's Global Constraints — every task's requirements include these:

- **User feedback is advisory, never authoritative.** A verdict is a signal to review, not a label. No feedback row changes a live assessment; no path writes `eval/dataset.json` without (a) an admin's explicit promote action and (b) a merged git PR.
- **RLS is not weakened.** `anon`/`authenticated` stay deny-all cross-user. Admins read across users by BYPASSRLS via `admin_ro`, never a `USING (true)` or role-checked policy. No client UPDATE/DELETE path is introduced.
- **The privileged key never reaches the browser.** All `/admin/*` data access is server-only. The privileged client module's first line is `import "server-only"`; its key is a non-`NEXT_PUBLIC_` env var. The browser holds only the two `NEXT_PUBLIC_*` values.
- **Edge auth is verified in-app, not trusted blindly.** `/admin/*` validates `Cf-Access-Jwt-Assertion` against the CF Access team JWKS before doing anything; missing/invalid returns **404, not 403** (no existence leak).
- **Feedback is bounded server-side.** `note` carries a DB `CHECK length(note) <= 2000`; `verdict` is a CHECK enum; `wrong_finding_id` is validated against the referenced investigation's findings **at promote time**, not trusted from the client. Client zod is not a trust boundary.
- **The CI gate is scoped, not blanket.** The live-eval job blocks merge **only** on PRs touching the band's decision surface (rubric, the four prompt nodes, model-env defaults, or the dataset). Model-env-only swaps are covered by a scheduled + `workflow_dispatch` run.
- **Migrations are operator-applied; their tests are text assertions**, not executed SQL — follow `apps/api/tests/migrations/`. **Never** run `supabase db push`, `supabase gen types`, `psql`, or start a database. Migration/SQL files are authored and reviewed only.
- **Test commands:** web `cd apps/web && pnpm vitest run <path>`; API/eval/script `cd apps/api && uv run pytest <path> -v`.
- Per project convention, **the commit step is omitted** from every task in this plan.

Create `supabase/migrations/20260826010000_feedback.sql`:

```sql
-- Component 1 (feedback→eval loop). A user's structured verdict on their OWN
-- investigation. Advisory only: a row here is a "review this" signal, never a
-- label and never a mutation of a live assessment (spec Global Constraints).
-- RLS scopes every row to its owner exactly like every other user-data table;
-- admin_ro reads across users by BYPASSRLS (20260826130000), never a policy.
-- Idempotent: guarded create + drop-then-create policies/trigger so re-running
-- `db push --include-all` is safe.
create table if not exists feedback (
  id uuid primary key default gen_random_uuid(),
  investigation_id uuid not null references investigations(id) on delete cascade,
  user_id uuid not null default auth.uid(),
  verdict text not null check (verdict in ('agree','too_high','too_low')),
  wrong_finding_id text,
  note text check (note is null or char_length(note) <= 2000),
  created_at timestamptz not null default now()
);

-- One verdict per (user, investigation): a resubmission is rejected, not stacked
-- into duplicates a spammer could use to flood the triage queue.
create unique index if not exists feedback_user_investigation_uniq
  on feedback (user_id, investigation_id);

alter table feedback enable row level security;

-- Own-row insert/select only. No update/delete grant to clients at all.
drop policy if exists feedback_insert_own on feedback;
create policy feedback_insert_own on feedback
  for insert to authenticated
  with check (user_id = auth.uid());

drop policy if exists feedback_select_own on feedback;
create policy feedback_select_own on feedback
  for select to authenticated
  using (user_id = auth.uid());

-- created_at + user_id are server-forced (security-review H1: never trust a
-- client timestamp or identity). BEFORE INSERT stamps now() and pins user_id to
-- the caller regardless of what the client sent. Empty search_path per the
-- security-advisor migration (20260826000000).
create or replace function feedback_force_server_fields()
returns trigger language plpgsql security definer set search_path = '' as $$
begin
  new.created_at := now();
  new.user_id := auth.uid();
  return new;
end $$;

drop trigger if exists feedback_force_server_fields on feedback;
create trigger feedback_force_server_fields
  before insert on feedback
  for each row execute function feedback_force_server_fields();

-- NOTE: no grant to admin_ro here — that role is created in the LATER migration
-- 20260826130000_admin_ro_role.sql, whose guarded block grants SELECT on this
-- table once it exists.
```

- [ ] **Step 4: Append verify_rls.sql Case 21 (feedback own-row isolation)**

Append to `scripts/verify_rls.sql`, before the final `rollback;` if the file ends in a single transaction, otherwise as its own `do $$` block matching the Case 20 style:

```sql
-- -----------------------------------------------------------------------
-- Case 21 (feedback→eval loop, 20260826010000): a user cannot read another
-- user's feedback. Insert a row as user A, then attempt to SELECT it as user B
-- under the authenticated role; RLS must return zero rows.
-- -----------------------------------------------------------------------
do $$
declare
  a uuid := gen_random_uuid();
  b uuid := gen_random_uuid();
  inv uuid;
  visible int;
begin
  -- seed an investigation + feedback owned by A (definer context, RLS bypassed)
  insert into investigations (user_id, submission)
    values (a, jsonb_build_object('job_text', 'x')) returning id into inv;
  insert into feedback (investigation_id, user_id, verdict) values (inv, a, 'too_high');

  perform set_config('request.jwt.claims', json_build_object('sub', b)::text, true);
  set local role authenticated;
  select count(*) into visible from feedback where user_id = a;
  reset role;
  if visible <> 0 then
    raise exception 'Case 21 FAIL: user B saw % of user A''s feedback rows', visible;
  end if;
  raise notice 'Case 21 PASS: feedback is owner-isolated under RLS';
end $$;
```

Create `supabase/migrations/20260826010100_eval_candidate.sql`:

```sql
-- Component 2: the staging area between "admin approved" and "in the dataset".
-- Internal table — deny-all under RLS (like cache/checkpoints). Reached only by
-- the server-only privileged client (INSERT via admin_ro) and the operator
-- promotion script (SELECT/UPDATE via a privileged DB connection). No client
-- principal touches it. submission_snapshot is copied at promote time so a later
-- investigation edit can't mutate a pending case.
create table if not exists eval_candidate (
  id uuid primary key default gen_random_uuid(),
  investigation_id uuid not null references investigations(id) on delete cascade,
  submission_snapshot jsonb not null,
  expected_max_band text not null check (expected_max_band in ('LOW','MODERATE','HIGH','CRITICAL')),
  expected_band text check (expected_band is null or expected_band in ('LOW','MODERATE','HIGH','CRITICAL')),
  tags text[] not null default '{}',
  status text not null default 'promoted' check (status in ('promoted','exported')),
  promoted_by text not null,
  created_at timestamptz not null default now(),
  exported_at timestamptz
);

-- Deny-all: RLS on, zero policies. anon/authenticated can neither see nor write
-- it; admin_ro (INSERT grant, 20260826130000) and the operator script
-- (privileged connection) bypass RLS.
alter table eval_candidate enable row level security;

-- NOTE: no grant to admin_ro here — see 20260826130000_admin_ro_role.sql, whose
-- guarded block grants INSERT on this table once it exists.
```

```sql
-- -----------------------------------------------------------------------
-- Case 22 (feedback→eval loop, 20260826010100): eval_candidate is an internal
-- table — the authenticated role must see zero rows and be denied insert.
-- -----------------------------------------------------------------------
do $$
declare
  uid uuid := gen_random_uuid();
  inv uuid;
  visible int;
begin
  insert into investigations (user_id, submission)
    values (uid, jsonb_build_object('job_text', 'x')) returning id into inv;
  insert into eval_candidate (investigation_id, submission_snapshot, expected_max_band, promoted_by)
    values (inv, jsonb_build_object('job_text', 'x'), 'LOW', 'seed@example.com');

  perform set_config('request.jwt.claims', json_build_object('sub', uid)::text, true);
  set local role authenticated;
  select count(*) into visible from eval_candidate;
  if visible <> 0 then
    reset role;
    raise exception 'Case 22 FAIL: authenticated saw % eval_candidate rows', visible;
  end if;
  begin
    insert into eval_candidate (investigation_id, submission_snapshot, expected_max_band, promoted_by)
      values (inv, jsonb_build_object('job_text', 'y'), 'LOW', 'attacker@example.com');
    reset role;
    raise exception 'Case 22 FAIL: authenticated was allowed to insert eval_candidate';
  exception when insufficient_privilege then
    reset role;
    raise notice 'Case 22 PASS: eval_candidate is deny-all to authenticated';
  end;
end $$;
```

```ts
import "server-only";
import { createRemoteJWKSet, jwtVerify } from "jose";

// CF Access verification for /admin/*. Cloudflare Access puts a signed JWT in
// the Cf-Access-Jwt-Assertion header once a request clears the email allowlist.
// We DO NOT trust it blindly (spec Global Constraints): verify it against the
// team's JWKS + audience before doing anything. A missing/invalid assertion is
// an AdminAccessError, which every /admin/* surface maps to 404 — never 403, so
// the route's existence never leaks even if a request reaches the origin around
// Cloudflare. Admin identity lives ONLY in CF Access; the app holds no is_admin
// column and no roles table.
export class AdminAccessError extends Error {}

// Module-level singleton so the JWKS is fetched+cached once per server process,
// not per request. Keyed off the team domain; jose handles the cache + rotation.
let jwks: ReturnType<typeof createRemoteJWKSet> | null = null;
function getJwks() {
  const team = process.env.CF_ACCESS_TEAM_DOMAIN;
  if (!team) throw new AdminAccessError("CF_ACCESS_TEAM_DOMAIN unset");
  if (!jwks) {
    jwks = createRemoteJWKSet(new URL(`https://${team}/cdn-cgi/access/certs`));
  }
  return jwks;
}

export async function resolveAdminEmail(headers: Headers): Promise<string> {
  const assertion = headers.get("cf-access-jwt-assertion");
  if (!assertion) throw new AdminAccessError("missing Cf-Access-Jwt-Assertion");

  const aud = process.env.CF_ACCESS_AUD;
  if (!aud) throw new AdminAccessError("CF_ACCESS_AUD unset");

  let email: unknown;
  try {
    const { payload } = await jwtVerify(assertion, getJwks(), {
      issuer: `https://${process.env.CF_ACCESS_TEAM_DOMAIN}`,
      audience: aud,
    });
    email = payload.email;
  } catch (e) {
    throw new AdminAccessError(`invalid assertion: ${(e as Error).message}`);
  }

  if (typeof email !== "string" || !email) {
    throw new AdminAccessError("verified assertion carried no email");
  }
  return email;
}

// Alias used by /admin/* route handlers and server actions; identical behavior.
export const assertAdmin = resolveAdminEmail;
```

Note: the `issuer` option is included for completeness; if a CF Access deployment's `iss` differs, relax it in the operator step. The test mocks `jwtVerify`, so it asserts the `audience` option and does not depend on issuer.

```ts
import { updateSession } from "./lib/supabase/middleware";

export async function middleware(request: NextRequest) {
  // Cheap first cut for /admin/*: a request with no CF Access assertion never
```

```ts
"use server";

import { headers } from "next/headers";
import { revalidatePath } from "next/cache";
import { assertAdmin } from "../../../lib/admin/access";
import { supabaseAdmin } from "../../../lib/supabase/admin";
import type { Investigation } from "../../../lib/investigations";

export class PromoteError extends Error {}

const BANDS = ["LOW", "MODERATE", "HIGH", "CRITICAL"] as const;
type Band = (typeof BANDS)[number];

export interface PromoteInput {
  expectedMaxBand: Band;
  tags: string[];
  wrongFindingId: string | null;
  promotedBy: string;
}

// Pure, testable core: turn an investigation + admin correction into the
// eval_candidate INSERT row. wrong_finding_id is validated HERE against the
// referenced investigation's real findings (spec Global Constraints: never
// trust it from the client), then dropped — it's a triage signal, not part of
// the dataset case. submission_snapshot is copied so a later investigation edit
// can't mutate a pending case.
export function buildCandidate(inv: Investigation, input: PromoteInput) {
  if (!BANDS.includes(input.expectedMaxBand)) {
    throw new PromoteError(`bad expected_max_band: ${input.expectedMaxBand}`);
  }
  if (input.wrongFindingId) {
    const ids = new Set((inv.findings ?? []).map((f) => f.id));
    if (!ids.has(input.wrongFindingId)) {
      throw new PromoteError(`wrong_finding_id ${input.wrongFindingId} not in investigation ${inv.id}`);
    }
  }
  return {
    investigation_id: inv.id,
    submission_snapshot: inv.submission,
    expected_max_band: input.expectedMaxBand,
    tags: input.tags,
    promoted_by: input.promotedBy,
  };
}

export async function promote(formData: FormData) {
  const email = await assertAdmin(await headers()); // throws -> caller shows 404
  const investigationId = String(formData.get("investigation_id") ?? "");
  const expectedMaxBand = String(formData.get("expected_max_band") ?? "") as Band;
  const wrongFindingId = (formData.get("wrong_finding_id") as string | null) || null;
  const tags = String(formData.get("tags") ?? "")
    .split(",")
    .map((t) => t.trim())
    .filter(Boolean);

  const { data: inv, error } = await supabaseAdmin
    .from("investigations")
    .select("id, submission, findings")
    .eq("id", investigationId)
    .single();
  if (error || !inv) throw new PromoteError(`investigation ${investigationId} not found`);

  const candidate = buildCandidate(inv as unknown as Investigation, {
    expectedMaxBand,
    tags,
    wrongFindingId,
    promotedBy: email,
  });

  const { error: insErr } = await supabaseAdmin.from("eval_candidate").insert(candidate);
  if (insErr) throw new PromoteError(insErr.message);

  revalidatePath("/admin/feedback");
}
```

Create `apps/api/scripts/promote_feedback.py`:

```python
"""Component 8: turn admin-approved eval_candidate rows into dataset-shaped
cases, append them to eval/dataset.json, and mark the candidates exported.

The output is a DIFF for a human to open as a PR — this script never commits or
pushes, and never writes the dataset without an admin having promoted the
candidate first (spec Global Constraints: no silent write to canon).

Pure transforms (`candidate_to_case`, `append_new_cases`) are unit-tested with
no DB. `main()` reads/updates eval_candidate over a privileged DB connection
(operator env PROMOTE_DATABASE_URL) — not exercised in CI, like the repo's other
DB-gated code.

Run:
    cd apps/api && PROMOTE_DATABASE_URL=... uv run scripts/promote_feedback.py
"""
from __future__ import annotations

import json
import os
import pathlib
from typing import Any

DATASET = pathlib.Path(__file__).resolve().parents[1] / "eval" / "dataset.json"

_BANDS = ("LOW", "MODERATE", "HIGH", "CRITICAL")


def candidate_to_case(candidate: dict[str, Any], seq: int) -> dict[str, Any]:
    """Dataset-shaped case with a stable, collision-free id.

    id = feedback_<investigation_id[:8]>_<seq>. Two candidates from the same
    investigation stay distinct by seq. Tags always include 'source:feedback'
    for provenance; origin_investigation_id keeps traceability back to the run.
    """
    inv = str(candidate["investigation_id"])
    max_band = candidate["expected_max_band"]
    if max_band not in _BANDS:
        raise ValueError(f"bad expected_max_band: {max_band}")
    tags = list(candidate.get("tags") or [])
    if "source:feedback" not in tags:
        tags.append("source:feedback")
    return {
        "id": f"feedback_{inv[:8]}_{seq}",
        "description": f"Promoted from feedback on investigation {inv}.",
        "submission": candidate["submission_snapshot"],
        # The loader requires expected_band; fall back to the ceiling when the
        # admin only set a max.
        "expected_band": candidate.get("expected_band") or max_band,
        "expected_max_band": max_band,
        "tags": tags,
        "origin_investigation_id": inv,
        "v1_only": False,
    }


def append_new_cases(
    dataset: list[dict[str, Any]], candidates: list[dict[str, Any]]
) -> tuple[list[dict[str, Any]], list[str]]:
    """Append candidates not already present. Idempotent: an id already in the
    dataset is skipped, so re-running never duplicates. Returns (new_dataset,
    appended_ids)."""
    existing = {c["id"] for c in dataset}
    out = list(dataset)
    added: list[str] = []
    # Seq is per-investigation so re-promoting one investigation twice yields
    # _0, _1 rather than colliding.
    per_inv: dict[str, int] = {}
    for cand in candidates:
        inv = str(cand["investigation_id"])
        seq = per_inv.get(inv, 0)
        case = candidate_to_case(cand, seq)
        per_inv[inv] = seq + 1
        if case["id"] in existing:
            continue
        existing.add(case["id"])
        out.append(case)
        added.append(case["id"])
    return out, added


def main() -> None:  # pragma: no cover - DB-bound operator entrypoint
    import psycopg  # local import so unit tests need no driver

    url = os.environ["PROMOTE_DATABASE_URL"]
    dataset = json.loads(DATASET.read_text())
    with psycopg.connect(url, autocommit=False) as conn:
        rows = conn.execute(
            "select id, investigation_id, submission_snapshot, expected_max_band, "
            "expected_band, tags from eval_candidate where status = 'promoted' "
            "order by created_at"
        ).fetchall()
        cols = ["id", "investigation_id", "submission_snapshot", "expected_max_band", "expected_band", "tags"]
        candidates = [dict(zip(cols, r)) for r in rows]

        new_dataset, added = append_new_cases(dataset, candidates)
        if not added:
            print("No new candidates to promote.")
            return

        DATASET.write_text(json.dumps(new_dataset, indent=2) + "\n")
        conn.execute(
            "update eval_candidate set status = 'exported', exported_at = now() "
            "where status = 'promoted'"
        )
        conn.commit()
    print(f"Appended {len(added)} case(s): {', '.join(added)}")
    print("Review `git diff apps/api/eval/dataset.json` and open a PR — nothing was committed.")


if __name__ == "__main__":  # pragma: no cover
    main()
```
